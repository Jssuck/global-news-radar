# 清洗管线质量控制（Cleaning Pipeline QC）

## 概述

三级管线的每一级都有独立质量闸门，任一级指标跌破阈值即阻断进入下一级并进入死信队列（DLQ）。QC 的两条主线：**在线闸门**（每篇实时判定）与**离线抽检**（每周分层抽样人工/半自动复核）。指标定义与阈值见 `references/qc-metrics.md`。

## 在线闸门（每级出口必查）

1. **一级（规则清洗）出口**：正文非空、长度 ≥200 字符（通讯社快讯除外）、抽取语言与源 `language` 一致、URL 规范化 + SHA256 精确去重通过。任一失败 → 进兜底抽取链（newspaper4k/readability），仍失败 → DLQ
2. **二级（LLM 清洗）出口**：输出通过 JSON Schema 校验（标题/正文/发布时间/语种必填且类型正确）。校验失败重试 ≤2 次，仍失败 → DLQ 并计数为「LLM 格式失败」
3. **三级（LLM 整理）出口**：摘要 ≤200 字、分类标签 ∈ 受控词表、翻译语种字段合法；事件归并结果必须保留全部来源 URL 列表，禁止丢源

## 离线抽检（每周）

```bash
python3 scripts/qc_sample.py articles.jsonl --per-lang 20 --out batch.json
```

- 按语种分层抽样（每语种 20 篇，小语种全取），生成抽检批次
- 每篇人工判定三项：正文完整无 boilerplate 残留、摘要忠实原文、事件归并正确
- 批次合格率 <90% → 触发回归分析：定位到具体级别与组件，修复后重跑同批次

## 黄金样本回归（管线改动必做）

- 每源保留 ≥5 篇「黄金样本」（原文 HTML + 人工确认的期望抽取结果），html_list 策略源 ≥10 篇
- 修改抽取器、选择器、LLM prompt、Schema 后：全量重跑黄金样本集，逐字段 diff
- 回归通过率必须 100% 才可合并 PR；期望值本身需要修订时走单独 PR 并说明理由

## 变更隔离与回退（多变量改动必守）

- **一次只改一个变量**：抽取器升级与 LLM prompt 调整必须分 PR、分实验验证；组合故障时禁止跨组归因（如「抽取器组失败」不得归因给 prompt）
- 环境锁定：记录 commit SHA、依赖版本、模型版本、prompt 哈希、抽样 seed，保证实验可复现
- 量化门槛除质量指标外必须包含性能与成本：处理延迟 p95 涨幅 ≤10%、单篇 LLM token 成本涨幅 ≤5%，任一超标视同回归失败
- 回退预案带时限：自动触发条件（如 Schema 一次通过率 10 分钟内跌破 90%）、止血 ≤10 分钟、恢复 ≤30 分钟；重大版本上线前做一次回退演练

## DLQ 处置

- DLQ 条目保留原始 HTML 与失败原因，按失败类型聚类，每周清零一次：
  - 抽取失败集中某源 → 转入 **news-source-onboarding** 修复流程
  - 疑似地域封锁 → 转入 **geo-block-triage** 流程
  - LLM 格式失败率突增 → 检查模型版本/prompt 变更，回滚或降级到小模型重跑

## 质量红线

- 指标不达标不许「调阈值过关」——阈值变更必须经 milestone-gate-review 门禁评审
- 黄金样本与 DLQ 样本只存项目自用，不分发全文（合规红线）
